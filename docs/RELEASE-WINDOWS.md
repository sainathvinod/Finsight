# FinSight 2.0.0 — Windows Release

The Windows deliverable is a single file: **`FinSight-2.0.0-Setup.exe`**.

---

## For the person receiving FinSight

1. Download `FinSight-2.0.0-Setup.exe`.
2. Run it.
3. Launch FinSight from the Start Menu.

That is the whole procedure. You do **not** need to install Python, Qt, SQLite, SQLCipher, Visual
Studio Code, or set any environment variable — all of it is inside the installer. You do **not**
need administrator rights: FinSight installs into your own user profile.

### What happens on first launch

FinSight creates its encrypted review store under
`%LOCALAPPDATA%\FinSight\Stores\default\finsight.db`, protects the database key with Windows
DPAPI at current-user scope, runs its schema migrations, and opens on the review home screen.
No configuration is required and no terminal is involved.

### The optional assistant (Ask Fin)

Ask Fin explains results that FinSight has already calculated. It never computes a financial
value, creates a finding, or changes a review — and **FinSight's financial review is complete
without it**. Every number, finding, and report is produced with no AI configured at all.

Ask Fin needs a local AI runtime, which is not included in the installer (see *Why the AI runtime
is not bundled*). To set it up:

- tick **Set up Ask Fin** during installation, or
- use the **Set up Ask Fin** entry in the FinSight Start Menu folder at any time.

It downloads and installs the runtime and its language model (about 2 GB, once), then verifies
them. Everything runs on your machine; nothing is sent to a cloud service. If you skip it, decline
it, or have no internet connection, FinSight installs and works normally and Ask Fin simply
reports itself unavailable.

### Uninstalling

Uninstall from *Settings → Apps* or the Start Menu entry. It removes the application.

**Your review data is deliberately kept.** FinSight's retention model is non-destructive — an
uninstall must never silently destroy financial history or its audit trail. The encrypted store
under `%LOCALAPPDATA%\FinSight` remains, so reinstalling restores access to previous reviews. To
remove the data as well, delete that folder explicitly.

## For whoever cuts the release

### Building the installer

The installer is built by GitHub Actions on `windows-latest`. PyInstaller freezes the *host*
interpreter and bootloader, so a Windows installer cannot be produced from macOS or Linux.

**Tagged release** — push a tag beginning with `v`:

```bash
git tag v2.0.0 && git push origin v2.0.0
```

`.github/workflows/release-windows.yml` then builds, tests, packages, verifies, and publishes a
GitHub Release with the installer attached.

**Without tagging** — run *release-windows* from the Actions tab. The installer is attached to the
run as the `FinSight-Windows-Installer` artifact.

**On a local Windows machine** — `powershell -ExecutionPolicy Bypass -File build\windows\build_windows.ps1`.

### What the pipeline verifies before publishing

| Gate | Check |
|---|---|
| Dependencies | every runtime import resolves on Windows |
| Tests | the full suite |
| Architecture | import-linter contracts |
| Bundle | `FinSight.exe` exists; QtAwesome icon fonts are present |
| Launch | frozen executable starts and exits 0 (`FINSIGHT_SMOKE`) |
| Encryption | the created store is **not** plaintext SQLite |
| Lifecycle | silent install → launch → uninstall → **review data retained** |
| Identity | SHA-256, size, and commit recorded in `RELEASE-EVIDENCE.txt` |

## Why the AI runtime is not bundled

Recorded in full as **DEC-037**. In short:

- **Licensing.** Ollama is MIT and redistributable, but `llama3.2:3b` carries the separate Meta
  Llama Community License with attribution and acceptable-use obligations. Shipping model weights
  inside a commercial installer needs legal sign-off that does not yet exist (PKG-05).
- **Size.** Bundling would produce a ~3 GB installer, against a qualification target of restricted
  8–16 GB corporate laptops.
- **Optionality.** FR-095 requires the deterministic review to be complete with no AI provider.
  Making an AI runtime an install precondition would invert that guarantee.

Provisioning is therefore automatic *when chosen*, and absent otherwise.

## Known limitations of this release

- **The installer is not code-signed.** Windows SmartScreen will warn on first run ("Windows
  protected your PC" → *More info* → *Run anyway*). Signing needs the organization's Authenticode
  certificate (PKG-06). This is the single most visible rough edge for a non-technical recipient.
- **No SBOM or third-party notice bundle** (PKG-05).
- **Per-user install only.** Governed machine-scoped enterprise deployment (the WiX per-machine MSI
  proposed in ADR-V2-004) is a separate package and a separate decision.
- **Detection scope.** The engine ships five protected baseline rules; the delivered scope and the
  gap against the Rules Catalog are recorded in **DEC-036**. There is no month-over-month
  comparison in this release.
- **macOS is not released here.** A known second-launch keychain defect is documented at the top of
  `.github/workflows/release-macos.yml` and must be fixed before any macOS distribution.
